# nopeek — CLI for Claude Code Secret Safety

## Problem

When using cloud CLIs (AWS, Hetzner hcloud, kubectl, etc.) inside Claude Code sessions, secrets leak into:

- **Anthropic's API** — every Bash tool output is sent as conversation context, retained 30 days (commercial) to 5 years (consumer with training on), not encrypted at rest
- **Local transcript files** — `.jsonl` session files stored ~30 days on disk
- **Terminal scrollback** — standard risk but compounded by the above

There is no built-in redaction for Bash output in Claude Code today. A PreApiCall/PostApiCall hook has been requested (anthropics/claude-code#39882) but doesn't exist yet.

## Solution

`nopeek` is a CLI that acts as a **secure proxy between Claude Code and your secrets**. Claude knows key *names*, never key *values*.

1. **Loads** secrets from `.env` files into Claude Code sessions without exposing values — Claude asks nopeek for keys, nopeek injects them via `CLAUDE_ENV_FILE`, values never appear in conversation context or transcripts
2. **Scans** your machine for installed cloud CLIs and their auth configuration
3. **Migrates** credentials to profile-based auth (the safe pattern)
4. **Generates** Claude Code hooks (SessionStart + PreToolUse) for automatic secret loading and output redaction
5. **Stores** arbitrary keys securely for repeated use across sessions
6. **Audits** `.env` files and warns about exposed secrets

### Load secrets from .env files

Claude Code's deny rules block direct `.env` reads (`Read(.env)`, `Bash(cat .env)`). nopeek acts as a secure proxy — Claude asks nopeek for keys, nopeek reads the file and injects values into the session environment. Claude never sees the values.

```bash
# Load all keys from .env into the session
npx nopeek load .env

# Output (no values shown):
#   Loaded 3 keys from .env:
#     DATABASE_URL
#     STRIPE_SECRET_KEY
#     AWS_SECRET_ACCESS_KEY
#   Keys are now available as environment variables in this session.
```

```bash
# Load specific keys only
npx nopeek load .env --only DATABASE_URL,API_KEY
```

Behind the scenes, nopeek writes `export KEY=value` to `CLAUDE_ENV_FILE`. Claude's subsequent Bash commands can use `$DATABASE_URL` etc. without the values ever appearing in conversation context or transcripts.

### Set arbitrary keys

```bash
npx nopeek set MY_API_KEY                    # prompts for value interactively (not in Claude)
npx nopeek set STRIPE_SECRET_KEY --from-env  # reads from current shell env
npx nopeek set HETZNER_TOKEN --value "abc"   # inline (for scripting, not recommended in Claude)
```

Stores the value in nopeek's secure config (`~/.config/nopeek/`). The SessionStart hook loads stored keys into `CLAUDE_ENV_FILE` at session start.


Shows current state: which CLIs are configured, which hooks are active, which arbitrary keys are stored.

## Architecture

### Storage

- Config file: `~/.config/nopeek/config.json` (or `$XDG_CONFIG_HOME/nopeek/`)
- Stores: CLI profile mappings, arbitrary key names + values, redaction patterns
- File permissions: `0600` (owner read/write only)

### Generated Hooks

**SessionStart hook** (`nopeek-session.sh`):

```bash
#!/bin/bash
# Generated by nopeek — loads credentials via CLAUDE_ENV_FILE
if [ -n "$CLAUDE_ENV_FILE" ]; then
  echo 'export AWS_PROFILE=default' >> "$CLAUDE_ENV_FILE"
  echo 'export HCLOUD_CONTEXT=default' >> "$CLAUDE_ENV_FILE"
  # Arbitrary keys from nopeek config
  echo 'export MY_API_KEY=sk-abc123' >> "$CLAUDE_ENV_FILE"
fi
exit 0
```

**PreToolUse(Bash) hook** (`nopeek-redact.sh`):

Intercepts Bash commands. If the command involves a known cloud CLI, rewrites it to pipe stdout through a redaction filter. Known patterns:

- AWS access keys: `AKIA[A-Z0-9]{16}`
- AWS secret keys: 40-char base64 after `SecretAccessKey`
- Bearer tokens: `Bearer [a-zA-Z0-9._-]+`
- Generic API keys: `sk-[a-zA-Z0-9]+`, `sk_live_*`, `sk_test_*`
- Hetzner tokens: 64-char hex strings
- Private keys: `-----BEGIN.*PRIVATE KEY-----`
- Connection strings with passwords: `://[^:]+:[^@]+@`
- Base64-encoded long strings in known secret fields

### Hook Registration

Hooks are registered in `~/.claude/settings.local.json` under the `hooks` key, following the Claude Code hooks schema:

```json
{
  "hooks": {
    "SessionStart": [{
      "hooks": [{
        "type": "command",
        "command": "~/.claude/hooks/nopeek-session.sh"
      }]
    }],
    "PreToolUse": [{
      "matcher": "Bash",
      "hooks": [{
        "type": "command",
        "command": "~/.claude/hooks/nopeek-redact.sh"
      }]
    }]
  }
}
```

## CLI Detection Matrix

| CLI | Auth check | Safe pattern | Migration |
|-----|-----------|-------------|-----------|
| `aws` | `~/.aws/credentials` + `AWS_ACCESS_KEY_ID` in env | Named profiles (`AWS_PROFILE`) | Move env vars to `~/.aws/credentials` profile |
| `hcloud` | `~/.config/hcloud/cli.toml` | Named contexts (`HCLOUD_CONTEXT`) | Already context-based, just set env var |
| `kubectl` | `~/.kube/config` | Kubeconfig contexts | Usually already fine |
| `doctl` | `doctl auth list` | Auth contexts | `doctl auth init` |
| `gcloud` | `~/.config/gcloud/` | Named configs | `gcloud config configurations` |
| `az` | `~/.azure/` | Service principals / managed identity | `az login` profiles |
| `terraform` | Various backend configs | Env vars / backend config | Move inline creds to env |

Start with **aws + hcloud** (author's actual use cases). Others can be added incrementally — each CLI is a self-contained detector module.

## Constraints

- **No daemon / no runtime dependency** — nopeek is a setup tool that generates static hook scripts. After `init`, nopeek itself doesn't need to be running
- **Non-destructive** — migrations always back up the original config before modifying
- **Transparent** — every generated file is human-readable, every action is logged to stdout
- **Offline** — no network calls, no telemetry, no updates

## Tech Stack

- TypeScript, built with `bun` (or `tsup` for npm compatibility)
- Zero runtime dependencies (or minimal: just a CLI framework like `commander`)
- Published to npm as `nopeek`

## Limitations (be honest in README)

- **PreToolUse redaction is best-effort.** Regex patterns catch known formats but can't catch every possible secret. This is a safety net, not a guarantee
- **`CLAUDE_ENV_FILE` values are written to a temp file on disk.** The file is session-scoped and cleaned up, but the values exist on disk briefly
- **No PostToolUse output redaction for Bash.** Claude Code doesn't support modifying Bash output after execution (only MCP tools via `updatedMCPToolOutput`). The PreToolUse approach rewrites the command to filter output before Claude sees it
- **Waiting on anthropics/claude-code#39882** — PreApiCall/PostApiCall hooks would be the definitive solution for redacting secrets from the API payload before it leaves the machine

## Out of Scope (for v1)

- GUI / TUI setup wizard
- Secret rotation
- Vault/1Password/Bitwarden integration
